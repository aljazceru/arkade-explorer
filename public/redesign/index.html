ark.observer / redesign
01 Signal 02 Datasheet 03 Atlas Compare
Design proposals · November 2026

Three ways to make ark.observer an instrument, not a template.

Each proposal is a working prototype built on the same real mainnet capture, so you can open the same transaction, commitment or address in all three and compare like for like. The switcher in every prototype keeps you on the record you are looking at.

01 · Console Signal Dark, dense, keyboard-first. Everything live, nothing decorative. 02 · Reference Datasheet Light, print-grade, chart-led. Read the network like an instrument. 03 · Map Atlas Spatial, structure-first. See where every sat sits.
00 · Why redesign

Today it looks like a starter kit.

The data underneath is good. The interface hides it behind template patterns, so the states that matter (expiring coins, where funds are anchored, what an operator actually guarantees) never stand out.

Findings
  1. Template layout. Centered hero, four icon KPI cards and rounded cards around everything: no hierarchy, low density.
  2. Provenance as noise. "snapshot 18d ago · may be stale" sits next to the figures instead of being stated once, clearly.
  3. Every row is green. "Confirmed" pills on every on-chain row; renew and expired states never stand out.
  4. Ids you cannot follow. Truncated hashes with no way to relate the same id across views.
  1. Detail pages explain nothing. Raw outpoints in boxes; no anchor, lineage or exit context; expiry only as a date.
  2. Mixed units. "~7 days" beside "4,032 blocks"; parameters dumped without saying what they mean for a holder.
  3. Type. Courier New for all data and a trial-licensed display face (TT Firs Neue Trial).
  4. Same answer for everyone. Visitors, holders and operators get one page with no path to the job they came for.

Signature

  • Live tape. Tip, fees, both operators, next round, 24 h activity in one strip.
  • Hash chips. Identicon per id, so the same id is recognisable everywhere.
  • Time strip is the filter. Brush 24 h / 7 d / 45 d to filter the table.
  • Query bar. net:arkade state:renew amt>10000, synced with toggles.
  • Inspector + trail. Follows the cursor; lifecycle rail to expiry; j k c w / ?.

Tradeoffs

  • Dense. First-time visitors lean on the ? overlay.
  • Dark-first. Needs a light variant mapped onto Dawn.
  • Easy to get wrong. Without the details it becomes "another dashboard".

Path to production · S–M

  • Evolves the current Overview: records-table, record-detail, network-pulse.
  • New: HashChip, TimeStrip, QueryBar, shortcut map on use-keyboard-shortcut.
  • Tokens replace themes/midnight.css; no new data sources.
02 · Reference

Datasheet

Read the network like an instrument.

Open prototype →
For
Researchers, Bitcoiners comparing implementations, newcomers who need to understand.
Palette
Type

Signature

  • Readings. Plain-language sentences generated from the data, footnoted to sources.
  • Seismograph. Both operators on one Bitcoin-block axis.
  • Spec comparison. Arkade vs Second in normalised units, differences explained.
  • Expiry horizon. Every observed unspent VTXO on a 31-day ruler, exit window hatched.
  • Stratigraphy. The unroll path from Bitcoin up: exit depth made visible. Prints as A4.

Tradeoffs

  • Long scroll. Slower to triage than a console.
  • Light-only. Needs a dark variant for night use.
  • Copy must be right. Generated sentences need careful edge-case tests.

Path to production · M

  • Readings are pure functions in src/lib, unit-tested like the rest.
  • SVG chart components (seismograph, horizon, strata); new type scale and grid.
  • Print stylesheet; no new data sources.
03 · Map

Atlas

See where every sat sits.

Open prototype →
For
Anyone tracing funds, auditing exit safety, or learning how Ark works.
Palette
Type
Instrument Sans · Martian Mono
390 px

Signature

  • The Ark layer. One time axis: Arkade and Second lanes over a Bitcoin block rail.
  • Unroll path. A route from a VTXO to its commitment; exit depth as the headline.
  • Flow graph. Inputs → tx → outputs, rings show lifetime left.
  • Constellation. An address's VTXOs clustered by batch.
  • Lifetime bars. VTXO lifetime vs exit window: safety margins side by side.

Tradeoffs

  • Most novel. Highest learning curve and most engineering.
  • Scale. Layout must hold for 600-hop chains and 1,500-VTXO addresses.
  • Mobile. Canvases need deliberate pan and stack behaviour.

Path to production · L

  • Needs per-entity getVtxoChain (already used by the exit flow).
  • An SVG layout layer (time scale, lanes, collision handling, chain compression).
  • Detail pages rebuilt around the graph; tables become the secondary view.

Decision

03 Atlas was selected and is now the production UI, running on live data. The recommendation below is kept as written at review time.

Recommendation

Ship Signal as the shell: it is the shortest path from today's code and gives repeat visitors the most per glance.

Then borrow the two ideas no other explorer has: Datasheet's Readings on every detail page, so newcomers know what they are looking at, and Atlas's unroll path with exit depth on every transaction and coin, because that is the number a holder cannot get anywhere else.

Prototypes use one real mainnet capture; nothing on these pages is live. Fonts: Geist, Geist Mono, Archivo, IBM Plex Mono, Instrument Sans, Martian Mono (SIL OFL 1.1).
